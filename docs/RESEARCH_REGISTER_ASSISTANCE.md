# Selective assistance

[Research register](RESEARCH_REGISTER.md)

Explorer already has six software roles, a common MuJoCo world, a mechanism to request a skill, and a copy of an upstream allocation algorithm. The open research question is whether a recipient can identify a missing piece of information **before taking an action**, obtain it from a second robot, and use it to improve an independently observed outcome at a measured cost. The evidence below separates these steps.

The completed shared-world camera intervention now meets the donor-to-recipient requirement. It also changes the strongest baseline. A recipient with three seconds to turn its own camera completed all 24 open-room scenes. The follow-up separates active local sensing and a useful peer viewpoint with an opaque screen. Two particularly close precedents change the novelty claim. In the D-optimal viewpoint study, a mobile monitoring robot moves its camera to support another robot's grasp and placement. The manipulator in that setup relies on external visual sensing. In *Proactive collaboration via autonomous interaction*, heterogeneous robots recruit peers based on task need in both physical and simulated settings. Autonomous recruitment and assistance by a mobile camera already have physical precedents. Explorer's proposed contribution is to isolate **when the extra observation improves the recipient's endpoint** against equal-budget random dispatch while the recipient can also sense and act alone. Include a cheap baseline that requests a new view whenever the recipient loses the marker. Compare a fixed donor pose against a pose selected for expected information gain at equal travel cost. [D-optimal viewpoint study](https://pmc.ncbi.nlm.nih.gov/articles/PMC12115303/) · [Proactive collaboration paper](https://doi.org/10.1038/s41467-026-72797-8) · [Authors’ deposited code and data](https://doi.org/10.5281/zenodo.19240700) · [Current donor camera scan](../explorer4/sim/cooperation.py)

The V2V4Real benchmark offers a concrete implementation of sensor sharing. Its late-fusion code transforms a second vehicle’s detection boxes into the receiving vehicle’s frame before combining observations. Its author-reported synchronous and asynchronous results differ, which motivates checking acquisition time. Explorer can use the same principle with a much smaller message. Send a measured target pose through timestamped transforms, retain the donor image ID, and score pose error against an independent mark. Compare that error and the final approach under correct, delayed and shuffled packets. [V2V4Real paper](https://openaccess.thecvf.com/content/CVPR2023/papers/Xu_V2V4Real_A_Real-World_Large-Scale_Dataset_for_Vehicle-to-Vehicle_Cooperative_Perception_CVPR_2023_paper.pdf) · [Late-fusion transform](https://github.com/ucla-mobility/V2V4Real/blob/main/opencood/data_utils/post_processor/voxel_postprocessor.py#L255-L286) · [Explorer world memory](../explorer4/world_memory.py)

In a field example, ROSMASTER logged a cube sighting. A later, separately commanded Tank approach consulted memory, travelled 0.89 m and reported a final distance of 0.39 m. Its child episode contains six frames. The two missions have separate IDs and no independent endpoint measurement. This is a useful trace of information reuse across machines. The causal comparison and autonomous decision to ask are still open. On Homebrain the records are in `episodes/20261115-223520-tank-goto/episode.json` and `world/memory.json` beneath the data root. ## How informative was the random baseline?

The reported cost-matched random run scored 35/40. Both potential motor-library outcomes were saved for every scene. This makes it possible to compute the entire distribution for uniform random assignment of 26 requests retrospectively. Across the 40 fixed scenes, asking improved three local outcomes, worsened two and left 35 unchanged. Of the 23,206,929,840 subsets of size 26, 21.71% reach or exceed the selective rule’s 38 holds. Uniform assignment averages 36.65 holds. This is an exact conditional comparison on these recorded scenes. Generalization to new scenes and physical helpers still requires new evidence. Reproduce it from the repository root with `python scripts/analyze_help_budget.py docs/results/research-audit-20261122/paired-simulation.csv`. ## Responsibility for each decision

The six [fleet roles and their skill registrations](../explorer4/fleet_agents.py#L1) are bounded code components. The optional [Qwen/smolagents planner](../explorer4/cognitive/model.py) proposes a finite plan. ROSMASTER and Tank edge agents own their local hardware interfaces. Homebrain coordinates trials, and SO-101 supplies demonstrations or a measured object description through its [existing station](../explorer4/so101_station.py). The proposed end-to-end trace should link these roles with a single request ID.

| Existing role | Responsibility in the proposed comparison |
| --- | --- |
| MissionCoordinator | Select a registered task, recipient and available donor. Keep the local-only option available on appropriate scenes. |
| SceneObserver | Record what each camera could see before the decision, with time, frame, uncertainty and transformations. |
| AssistanceBroker | Predict whether a particular donor can improve this trial at its cost, then dispatch once and accept timeout/refusal. |
| MemoryCurator | Save source episode and recipient policy, geometry and camera versions. Freeze memory before testing and exclude test outcomes from retrieval. |
| OutcomeVerifier | Verify the donor actually observed the target, the recipient used the returned estimate, and the task succeeded. Keep these three outcomes distinct. |
| LearningAndExperimentCurator | Register scene groups, data sources, interventions, model hashes, resource budget and results. Route uncertain cases to future training only after adjudication. |

## Minimum experiment for the article

Use an occluded dock or marked approach pose first. This isolates the value of a mobile observer from grasp failures. Prepare identical starts with occluded and visible targets, a busy or unavailable donor, and a moving-target or stale-packet condition. Capture donor and recipient images separately, plus a ground-truth verifier independent of both controllers. Compare local-only, always ask, cost-matched random and the calibrated decision on held-out scenes grouped by layout, object and recording session. Size the paired comparison from a separate pilot's discordant outcomes and the smallest useful effect. Publish task gains and losses with a paired interval, request rate, measured time and each failure reason. Freeze checkpoint, threshold, retrieval snapshot, seeds and scoring before evaluation. Treat the existing 40 pilot scenes as development evidence for any rule derived from them.

For physical verification, start only when simulated messaging changes the measured recipient behavior and the recipient can complete the target approach independently with a correct pose. At that point the operator must prepare the two selected platforms for a floor trial, clear the outstanding Tank STOP/feedback acceptance if Tank participates, verify the shared camera/map frame with a measured target, and set up the agreed visible and occluded positions. Record synchronized donor and recipient streams and an independent endpoint. Keep test setups separate from demonstrations. A software-only analysis or another teleoperated grasp cannot fill this evidence gap. SO-101 can remain outside the first two-robot experiment. Add its measured size and an observed closing axis as a separately testable extension.
